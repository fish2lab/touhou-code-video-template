# 教程：从零理解这条管线

面向「会写点代码、但没碰过动画和视频管线」的人。读完你应该知道：每个文件干什么、一帧是怎么画出来的、视频是怎么出的、改哪里能得到你要的效果。

## 0. 先认几个词

| 词 | 是什么 |
|---|---|
| `.mjs` | 就是 JavaScript，后缀 m 表示用 ES Module 写法（能 `import`）。`node tools/xxx.mjs` 等于 `python xxx.py` |
| `npm` / `package.json` | Node 的包管理。`package.json` 登记依赖和命令别名；`npm run render` 就是执行里面写的 `render` |
| Canvas 2D | 浏览器里一块画布，用代码一笔一笔画（`c.fill()`、`c.stroke()`）。整部片所有画面都在上面画 |
| Playwright | 用代码操控一个没有界面的浏览器：打开页面、执行 JS、截图 |
| ffmpeg | 命令行视频工具：把图像序列和音频编码成 MP4 |
| 全局作用域 | 本项目的 `<script>` 是经典脚本，不是模块，所有文件共用一个全局空间。所以每段的名字都要带前缀 |

## 1. 核心思想：画面 = f(t)

`src/core.js` 开头那句：**每一帧只由「全片时间 t」决定。**

- 入口是 `renderAt(ctx, t)`：给一个时间，画出那一刻的样子。播放、抽帧、出片调用的是同一个函数，所以看到的是同一张画。
- 因此不能存状态（上一帧画了什么不重要），也不能用 `Math.random()`。要「随机」就用带种子的 `hash(k, seed)` / `rng(seed)`：同一个 t，永远是同一个抖法。
- 好处：能跳到任意时刻（`?t=30`）；能把全片切成几段并行渲染；机器再慢，成片也稳。
- 对照：录屏是「让浏览器实时跑，同时录」。慢了就掉帧，和配音也很难对齐。

常用的时间工具（都在 `core.js`）：

```js
sm(a, b, tau)            // tau 在 [a,b] 秒内 0→1（带缓动），之前 0 之后 1
win(a, b, tau)           // [a,b] 里淡入淡出的可见度
key(tau, [[0,0],[2,1]])  // 关键帧插值，值可以是数或数组
easeIO / easeOut / easeOutBack / easeOutElastic ...   // 缓动函数，作为 sm/key 的第四/三参数
tick(t)                  // 手绘「抖」的种子，每秒换 8 次
twos(t)                  // 把时间吸到 12fps 网格（一拍两帧的手绘感）
```

## 3. 一段是怎么写的

看 `src/scenes/2-time.js`（最短的完整例子）；七位角色怎么摆在一起看 `src/scenes/1-cast.js`。一段只有三样东西：

1. **台词**：`seq(起始秒, [...])` 把一串台词排成 `[开始, 结束, 文字, 选项]`。选项里 `who: 'cirno'` 换说话人，`mood` 换表情，`pause` 句前停顿，`hold` 句后多停。时长默认按字数估算，有配音时自动改成「配音时长 + 0.35 秒」。
2. **画面函数** `draw(c, tau, L)`：`c` 是画布，`tau` 是段内时间，`L` 是当前台词的信息（谁在说、嘴型、表情）。里面先画 `spread(c, tau)`，再按 tau 算每个元素的状态，最后画两个角色。
3. **登记**：`scene({ order, key, title, dur, lines, fn })`。`dur` 是整段长度。

画具速查（完整签名看 `src/kit.js` 里每个函数上面的注释）：

```js
cutPaper(c, pts, color, {seed, step, blur})   // 一片剪纸：剪刀边 + 纸纹 + 软影；返回 Path2D
rline(c, pts, {w, color, p, t, seed})         // 一笔手绘线；p 是画出比例（0..1，做「一笔笔画出来」）；传 t 就每秒抖 8 次
zh(c, '文字', x, y, {size, p, align})         // 手写字；p 是逐字写出的比例，配合 writeP(tau, 起始, 文字, 每字秒数)
circPts / rectPts / starPts / heartPts        // 生成轮廓点，交给 cutPaper / rline
pop(c, x, y, k, fn)  fade(c, a, fn)           // 缩放进来 / 淡入地画 fn
popup(c, foldY, k, fn)  spin(c, x, y, a, fn)  // 立体书立起来 / 转盘
thread(c, a, b, {p, sag})  brassPin(c, x, y)  // 线和图钉
bubble(c, x, y, w, h, {tail})                 // 气泡
spread(c, tau)  pageHeader(c, '页名', tau, t0)   // 摊开的魔导书 + 页眉；BOOK.L / BOOK.R 是左右页
drawPatchouli(c, {...STD.pch, pose, mood, mouth, blink, t})   // 角色；姿势和表情见 src/character/*.js 文件头
```

## 4. 声音

`npm run voice` 做的事：从页面里取出全片台词 → 汉字转拼音（pinyin-pro，带多音字上下文）→ 转日文假名（`zh-kana.mjs`）→ 交给 AquesTalk 合成 → 每句一段 MP3，同时算出 30fps 的响度包络，让角色按真实音量张嘴 → 写进 `src/voice-data.js`。

- 改了台词就要重跑一次，并提交生成的文件。
- 拼音表里没有的词（拉丁字母、口癖）在 `tools/voice.mjs` 的 `WORDS` 里补读法；漏了会在终端打印「没读的字符」。**不要在台词里写单个字母**（比如 t、N），改成汉字说法。
- 背景音乐见下面「背景音乐」。
- 播放器和出片走同一个 `mixAudio`，听到的和成片一致。

### 背景音乐

**每集用这一集主讲角色（或首次登场角色）的角色曲**，拿原曲扒谱里的音符，用代码重新编配成八音盒版。第 5 集用的是古明地觉的「少女さとり ～ 3rd eye」，模板演示用帕秋莉的「ラクトガール ～ 少女密室」。

1. **找扒谱**：GitHub 上的 `AyHa1810/touhou-midi-collection` 按作品分目录，同一首曲子常有几个人扒的版本。优先 ZUN 原版 MIDI（红魔乡等早期作品有），其次挑轨数多、乐器分得开的版本（第 5 集用的 Hisaraito 版 18 轨）。MIDI 下载到仓库外，不进仓库。
2. **挑轨**：`node tools/bgm.mjs 曲子.mid --list` 列出每一轨的乐器、音符数、小节范围、音域；再用 `--bars 17,18 1-12` 逐小节打印候选轨，认出主旋律。同一段旋律常有两轨平行三度，取上面那条。要的四个声部：主旋律（mel）、副旋律（counter，可以没有）、伴奏（piano，选琶音或分解和弦那轨）、低音（bass）。鼓和十六分音符的密集低音不要，八音盒放不下。
3. **填表生成**：改 `tools/bgm.mjs` 顶上的 `SONG` 表（曲名、出处、取哪几小节、放慢后的速度、四个声部各取哪轨哪几小节；主旋律在 A、B 段换乐器时可以分段取，见第 5 集），跑 `npm run bgm -- 曲子.mid`，生成 `src/bgm-data.js`，要提交。小节范围挑首尾能接上的一整段，`score()` 会循环放。
4. **编配不用动**：`core.js` 的 `score()` 已经写好了：主旋律八音盒（正弦加一点二倍频）、副旋律同音色更轻、伴奏过低通的三角波、低音升一个八度，挂混响，全片最后 3 秒淡出。原曲多在 140–160 拍每分钟，放到 90 上下（`SONG.bpm`）才像八音盒。没有 `src/bgm-data.js` 时退回原来那首八音盒小曲。
5. **验收**：浏览器开 `index.html` 听一段，语音盖得住音乐就行（有语音时音乐压到 0.45）。发布文案「出处」里写明原曲、作品、ZUN 和扒谱来源。

## 5. 开发循环

```sh
npm install && npm run font            # 一次性：装依赖、下载字体
open index.html                        # 直接用浏览器开；?scene=time 只放一段；?t=30 从第 30 秒开始；空格暂停，←/→ 跳 5 秒
node tools/frames.mjs --scene time --grid 24         # 抽联系表 → out/frames/time-grid.jpg，一眼看完一段
node tools/frames.mjs --scene time --at 3,10.5       # 抽整帧 → out/frames/time-3.png
node tools/overlap.mjs --scene time                  # 穿模检查：报出人物包围框里有东西的时间段
npm run build                                        # 单文件页面 → dist/index.html（双击可看，不用网络）
npm run voice                                        # 改了台词后
npm run render                                       # 出片 → out/*.mp4（1080p 30fps）
```

没有图形界面的机器（云端 VM）：Playwright 要有浏览器。装 `npx playwright install --with-deps chromium`，或者设 `CHROMIUM=/usr/bin/chromium` 用系统自带的。

## 6. 出片是怎么出的（tools/render.mjs）

1. 起 N 个无界面浏览器（`--jobs`，默认 4），每个都打开同一个页面。
2. 把全片按帧数切成 N 段。每个浏览器对自己那段，逐帧：调用 `renderAt(t)` 画到画布上 → `toDataURL` 导出 JPEG → 通过管道直接写给一个 ffmpeg 进程（不落盘）。
3. N 段各自编码成 MP4，用 ffmpeg 拼接。
4. 页面里的 `OfflineAudioContext` 把配音和背景音乐混成一条 WAV，混进去，出最终 MP4。

实测速度：4 核云端 VM、1080p、3 个并行页面，约 1.7 倍实时（6 秒片段 10 秒）。4K 画布像素是 4 倍，会慢很多，建议放本地机器渲染：`node tools/render.mjs --scale 2` 可以出 4K（画布分辨率翻倍，逻辑画面仍是 1920×1080）。

## 7. 常见坑

- `c.filter`（模糊、阴影滤镜）在逐帧绘制里会让每帧慢几十倍。用 `cutPaper` 的 `blur`（`shadowBlur`）代替。
- 名字重复：两个文件顶层都写 `const T = ...` 不会报错，后面的静默覆盖前面。必须加段前缀。
- 脚本顺序：`index.html` 里 `<script>` 的顺序就是执行顺序。新增文件要加在 `film.js` 之前、依赖它的文件之后。
- 构建靠字符串匹配 `<!-- @scripts -->` 到 `<!-- @end -->` 之间的 `<script src>` 来打包，别改这个注释，也别在里面写内联脚本。
- 字体：霞鹜文楷，`npm run font` 下载到 `fonts/`（不进 git）。字体裁剪需要 `pip install fonttools brotli`，没有就内嵌完整字体（页面 25MB+）。

## 8. 用现成的亮点特效

`src/fx/` 里有 10 个从前几集提炼出来的特效（总览 `docs/亮点.html`，样张 `fx.html?fx=<id>`）。不用拷代码：

```html
<!-- index.html：props.js 之后、scenes 之前 -->
<script src="src/fx/_fx.js"></script>
<script src="src/fx/nap-fall.js"></script>   <!-- 要用哪个加哪个 -->
```

```js
// 整段就是这个特效，上面叠自己的东西
fxScene({ id: 'nap-fall', order: 3, lines: S3LINES, hold: 1, opt: { speed: 1 }, over: (c, tau, L) => { /* 两人、气泡 */ } });
// 或者当零件画：缩进书页右半边、晚 1.2 秒开始、循环
fxPlay('nap-fall', c, tau, { box: [BOOK.R.x, BOOK.R.y, BOOK.R.w, BOOK.R.h], t0: 1.2, loop: true, bg: false });
```

`opt` 可用：`t0`（第几秒开始）、`speed`、`loop`、`box`（等比缩进矩形并裁剪）、`bg`、`al`。完整说明在 `src/fx/_fx.js` 头注释，起手模板是 `src/scenes/_fx-scene-template.js`。想改特效本身的颜色、时间点、角色站位，看对应文件的头注释里的「复用」「分叉」两项。
